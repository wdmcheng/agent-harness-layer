## Context

当前 `ModelInvocationService` 已在 provider 副作用前建立稳定 `usage_call_id`、event capacity、durable settlement 与 shared-budget reservation，但 `ModelRouter` 仍接受请求直接指定 provider/model，`build_agent_execution_services()` 只注册 `FakeModelProvider` 并拒绝其他 provider。现有 Pydantic AI adapter 把 `Agent.run_sync()` 放进线程池；`future.cancel()` 只能停止等待，不能证明已经开始的网络请求被取消。

本 change 受 REQ-025、AC-077 至 AC-084、MOD-001、BGT-001、ADR-0001 和 ADR-0002 共同约束。它修改 config、registry、route、adapter、invocation、composition 和验证面，必须由单一 owner 串行实现。默认运行不能读 ambient provider key 或联网；真实请求需要后续单独授权。

锁定环境当前实际为 `pydantic-ai==2.5.0`、`openai==2.44.0`。已安装源码确认 `Agent.run()` 是 async API，`OpenAIChatModel` 可接收 `OpenAIProvider`，后者可接收显式 `AsyncOpenAI`/`httpx.AsyncClient`；`AsyncTenacityTransport` 与 `wait_retry_after` 也存在。最新版官方文档只证明这些概念当前仍受支持，具体实现只使用锁定版本已验证的签名。

## Goals / Non-Goals

**Goals:**

- 让一个显式 `openai-compatible` 非流式文本 deployment 经完整 Harness route/budget/audit/usage seam 运行。
- 把 endpoint、credential、模型范围、价格、deadline/retry/Bulkhead 和 capability 在网络副作用前冻结并可审计。
- 用异步 I/O 和保守 unknown 状态替代线程池假取消，同时保持 fake/local 与既有 durable settlement 不退化。
- 为 Phase 18.1 留下可扩展但尚不生产 delta 的 route/provider/attempt/result seam。

**Non-Goals:**

- 不生产 streaming delta，不改变 RUN-006/CLI reader，不实现 structured output、tool call、reasoning 或多 provider 运维。
- 不让 request、Agent YAML 或 provider SDK ambient env 选择 endpoint/credential。
- 不引入分布式全局 Bulkhead、Vault/KMS、动态 deployment CRUD、新 HTTP endpoint、依赖升级或数据库 migration。

## Decisions

### 1. Deployment 与 credential 使用显式 mapping

`ModelSettings` 改为 `default_deployment_id`、`deployments: dict[str, ModelDeploymentSettings]`、`credentials: dict[str, ModelCredentialSettings]` 与 `endpoint_policies: dict[str, ModelEndpointPolicySettings]`。Mapping key 是长度不超过 64、匹配 `[a-z][a-z0-9]*(?:_[a-z0-9]+)*` 的 canonical lower-snake ref：deployment 保存非敏感 route policy，credential entry 的 `value: SecretStr` 被排除序列化并带 `allowed_origins`；endpoint policy entry 冻结非空 policy version、适用 `provider_kind`、exact `allowed_origins`、允许的 completion classifier ref/version 集合与可选 provider-default endpoint catalog ref/version。三者只从品牌 `AGENT_HARNESS_*` typed config/受控 overrides 进入 composition，Agent descriptor、request 与 provider 原生 ambient env 都不能创建或修改 endpoint policy。环境路径采用 `AGENT_HARNESS_MODEL__CREDENTIALS__<REF>__VALUE` 及 `_FILE`。YAML key 必须已经 canonical；env segment 可用常规大写，但 loader 在 direct/`_FILE` 比较和 merge 前统一规范化，并拒绝空 segment、非法字符及 `Foo`/`FOO` 等多原始别名碰撞，避免来源优先级掩盖歧义。

选择 mapping 而不是 list，是为了让 env/`_FILE` 有稳定路径且 merge 不依赖数组下标。选择 typed credential entry 而不是 `token_env` 字符串，是为了禁止 runtime 再读 `os.environ`，并让 secret 与允许转发 origin 在同一校验边界绑定。

输入上界与价格同样不能由 deployment 自证。`ModelSettings` 另增 `model_catalogs: dict[str, ModelCatalogEntrySettings]`，entry 以 canonical ref + 非空 version 冻结 `provider_kind`、model、`request_shape_ref="single-user-text-no-tools"`/`v1`、`utf8-bytes-plus-envelope`/`v1`、非负 `input_envelope_token_bound`、`cost_enabled`、input/output price、price source ref/version 与 canonical digest。Cost enabled 时两项价格及来源 identity 必填且为有限非负值；cost disabled 时价格与来源均为 null，不解释为零价。Deployment 的每个真实 allowed model 只保存 catalog ref/version，不再拥有另一套权威 envelope/price；loader 通过 `config/model_catalog.py` 解析 entry，按 typed-config delta 的 `model-catalog/v1` canonical JSON/Decimal 公式重算 digest，并逐值验证 provider/model/request-shape/strategy/price/digest。Unknown/mismatch、复制值低报或高报、digest 漂移都在 reservation/permit/client/network 前 fail closed。Route、budget snapshot、operation identity 与公开 evidence 冻结 catalog ref/version/digest 和解析值；reload 只影响新 root，恢复不读 current catalog 补齐或改价。Fake 保留既有离线零成本 route，不要求真实目录，也不能借 fake 目录进入真实 composition。

首个 provider kind 只有 `fake` 和 `openai-compatible`。`provider_kind` 是冻结 deployment 的协议/构造族；兼容公共字段 `provider`、Agent policy provider、request provider assertion 与 adapter `provider_id` 在 Phase 18 必须逐字等于该值。`pydantic-ai` 只是私有 adapter 实现名，不是 route identity。真实 deployment 包含 allowed/default/fallback models、可选 base URL、显式 `endpoint_policy_ref/version`、timeouts、逐状态 retry、`max_attempts`、可选且版本化的 completion classifier、bulkhead、pricing、输入上界策略、prompt/output cap、静态最大 per-attempt token/cost ceiling 和 `text_completion` capability；deployment 的 policy ref/version、provider kind、canonical origin 与 classifier 必须逐值命中 `endpoint_policies` 中唯一 entry，未知或不匹配 fail closed。省略 base URL 时，该 policy 还必须绑定 `config/model_endpoints.py` 中受版本控制的只读 provider-default endpoint catalog ref/version，并由 catalog 解析官方默认 HTTPS URL，禁止依赖 SDK/env 默认值。digest 按 typed-config delta 的 `endpoint-policy/v1` canonical JSON 公式确定性派生并包含 catalog/classifier identity，不接受 deployment 或调用方自报受信结论。默认 profiles 只提交完整 fake deployment；真实 deployment 示例只放非敏感模板和注释，不能让缺 key 的默认 service profile失效。

### 2. Endpoint policy 校验 URL 与 exact origin，不做运行时猜测

Startup 使用 `config/model_endpoints.py` 的统一 normalizer 和只读 default catalog 校验 scheme、host、port、path 与禁止组件；随后解析 `endpoint_policies[ref]`，逐值检查 version、provider kind、exact origin、completion classifier 和可选 default catalog identity。Unknown ref/version、provider/origin/classifier/catalog mismatch 一律在 storage/queue/client/DNS/HTTP 前返回 `config.invalid`。Credential forwarding 再比较 lower-case host、scheme 与 effective port 组成的 exact origin。Base URL 可以保留 provider API path，但拒绝 userinfo、query、fragment、dot-segment 越界与 redirect。正式 profile 只允许 policy allowlist 中的 HTTPS origin；local HTTP 只接受显式开启且 policy 明确批准的 literal loopback IP。HTTP client 设置 `follow_redirects=False`、`trust_env=False`，避免 redirect 或 ambient proxy 扩大 credential 出口。规范化且已排除敏感组件的 canonical base URL 属于私有 frozen route/snapshot identity；公开 evidence 只保留 origin、endpoint policy/catalog/classifier ref/version 与 digest，不暴露完整 URL。

普通/官方 OpenAI-compatible endpoint 没有标准化的“本次 completion 未开始”信号，因此默认 `retryable_http_statuses=[]`，429/5xx response 一律不自动重试。只有 endpoint policy 显式绑定 ref=`trusted_response_header_not_started`、version=`v1` 时，私有 transport 才可把恰好一个 `X-Agent-Harness-Completion-State: not-started` 原始响应 header 归一化为 `completion_observed=false`。Header 名大小写不敏感，但值去除 OWS 后必须逐字匹配；缺失、重复、逗号合并、多值、畸形、其他值、非绑定 policy/version 或 body/exception message 伪造均为 unknown。Response id、usage 或部分业务结果始终覆盖该 false 信号为 observed/unknown 并禁止 retry。Classifier identity 进入 endpoint digest、route、snapshot 和公开安全 evidence。

不通过运行时 DNS 探测决定信任，因为解析结果会漂移并引入 startup 网络；信任来自 committed/override exact-origin policy。其代价是部署者必须明确维护 allowlist，但这是 secret forwarding 可审计所需的成本。

### 3. Route intent 只缩权，route plan 真正不可变

Agent model policy 保留现有 `provider/default_model/fallback_models` 兼容字段，并增加 `deployment_id` 与 `allowed_models`。`ModelRequest` 增加可选 `deployment_id`；兼容 `provider` 变为可选相等断言，不再选择 provider。Phase 18 的唯一身份关系是 `ModelRequest.provider`（若提供）=`AgentModelPolicy.provider`=`ModelDeploymentSettings.provider_kind`=`ModelRoutePlan.provider`=`ModelProvider.provider_id`；route evidence 的 `provider_kind` 与 `provider` 也必须逐字相等。`pydantic-ai`、`openai` 等 SDK/adapter 名不进入该链。Request 不提供 endpoint/credential 字段并保持 `extra=forbid`：原始请求携带这些字段时 DTO 边界返回 `model.request_invalid`，不进入 router；router 只对 deployment/model/provider assertion/capability 分别返回 `model.route_not_allowed` 或 `model.capability_unsupported`。

Router 按 deployment policy → Agent frozen sub-snapshot → request 的顺序求交集，生成 frozen `ModelRoutePlan`。真实纯文本 route 的输入上界 strategy identity 固定为 `input_bound_strategy_ref="utf8-bytes-plus-envelope"`、`input_bound_strategy_version="v1"`，且必须与唯一受信 model catalog entry 的 provider/model/request-shape/strategy/ref/version/digest 逐字匹配：先拒绝超过 `max_prompt_utf8_bytes` 的 prompt，再用 checked arithmetic 计算 `trusted_input_token_bound=len(prompt.encode("utf-8"))+input_envelope_token_bound`；catalog entry 必须保证本 change 的单 user prompt、无 instructions/message history/tools 请求的全部 billable input tokens 不超过该值。Request 的 `max_output_tokens` 只能在 `1..deployment.max_output_tokens` 内缩小，并冻结为 `output_token_cap`。Deployment 静态 `max_per_attempt_token_bound` 必须等于 `max_prompt_utf8_bytes+input_envelope_token_bound+max_output_tokens`；cost 启用时静态 `max_per_attempt_cost_bound` 必须等于 `(max_prompt_utf8_bytes+input_envelope_token_bound)*input_token_price_usd+max_output_tokens*output_token_price_usd`，两项价格与 price-source identity 必须一同冻结；cost disabled 时目录价格、price-source identity、静态与动态 cost bounds 均为 null。Router 对具体调用计算动态 `per_attempt_token_bound=trusted_input_token_bound+output_token_cap`；cost 启用时计算动态 `per_attempt_cost_bound=trusted_input_token_bound*input_token_price_usd+output_token_cap*output_token_price_usd`，二者必须不超过已验证的静态 ceiling。Catalog unknown/mismatch、deployment 自报低报或高报、静态 ceiling 低报或高报、缺 strategy/价格或来源 identity、公式不一致、溢出或 prompt/output 超界都在 reservation、permit、client 和网络前以 `config.invalid` 或 `budget.reservation_rejected` 拒绝。

Plan 私有字段包含 deployment/provider/model、canonical base URL（含安全 path）、endpoint origin、endpoint policy ref/version/digest、model catalog ref/version/digest、request-shape、completion classifier ref/version、credential ref identity、capability、受信价格 identity/值、输入上界 strategy/envelope、prompt bytes、input bound、output cap、deadline/retry/bulkhead policy、上述每 attempt trusted bounds、`max_attempts`、checked calling reservation 上界与 snapshot schema version；公开 evidence 投影同一安全 identity/bounds，但不含 prompt、classifier header 原值或完整 URL。后续预算、adapter 和 evidence 只消费该 plan，不再读取 request 或 mutable settings决定路由、catalog、classifier 或 cap。Fallback 只在同一冻结交集内重新做 hard eligibility、公式复算与预算判断，真实失败绝不切 fake。

保留兼容 provider 断言而不是立刻删除字段，可减少现有业务 Agent 和测试迁移面；但断言不匹配时 fail closed，因此不会保留扩权能力。Shared-budget 新 snapshot 使用 `schema_version="budget-tree-v2"` 与 `budget-tree-v2:` id，完整保存 deployment/allowed models、canonical base URL、endpoint policy identity、model catalog ref/version/digest 及解析的 request-shape/strategy/envelope/price、completion classifier identity和 attempt bounds。恢复从 snapshot 逐值重建旧 route，禁止从 current settings 重选同 origin 的新 path、model catalog 或 classifier；credential secret 仍只按冻结 ref 从当前 typed secret boundary 解析，缺失或不再允许该冻结 origin 时 fail closed。`budget-tree-v1:` 仅在无 schema version、旧 required shape 完整且 provider 为 `fake` 时，从快照自身字段投影 synthetic legacy fake route；id/schema 混合、字段部分缺失、v1 real provider 或需当前 settings 补齐时返回 `budget.reservation_rejected`/`snapshot_invalid` 并进入安全人工处理。现有 string/JSON 列足够，因此不改数据库 schema；SQLite 与 PostgreSQL 都锁定同 origin 不同 path 的恢复合同。

### 4. Provider protocol 改为 async，并用 provider-neutral permit 固定副作用顺序

`ModelProvider.complete()` 与 `ModelRouter.execute()` 改为 async；`ModelInvocationService` 直接 `await`，删除线程池 timeout。Fake provider 同步计算但以 async protocol 返回，保持确定性。核心新增不含 vendor 对象的 `PreparedModelCall`/`ModelExecutionPermit`。唯一顺序固定为：先形成 immutable route plan 并完成 prompt/output/model-catalog/公式等动态 hard eligibility → 执行 soft policy/fallback/approval 并通过既有 `PolicyEngine` 写耐久 `policy.decision` audit → 建立预算和 settlement reservation → 取得 process-local deployment permit（此时不得联网）→ 从 composition 注入的私有 client factory 获取或构造绑定该 plan 的 client lease → 提交 durable `side_effect_started` → adapter send。Policy check 固定为 bound execution identity、`action="model.invoke"`、`resource="agent:<agent_id>:model"`，安全 context 只含 tenant/run/agent/request/trace、冻结 route/catalog identity、reservation bounds 与 soft-limit decision；返回的 `audit_ref` 是唯一授权成功审计，不新增 CanonicalEvent、不占 event capacity，且不能冒充 provider 已开始。Hard eligibility、soft policy deny 或 approval-required 未获批准时，reservation/permit/client/mark/network 全部为零；approval 只能缩小 route 或继续原 intent，不能提高、重置或覆盖 owner shared hard limit。Client 构造不得联网；构造失败按 not-started 回滚本调用 reservation/permit。Durable mark 前任何边界收到外部取消时，必须取消尚未完成的本地工作、释放或归还 client lease、permit 与 reservation，保持零 durable mark/零 provider 网络副作用，并以 `model.invocation_cancelled` 结束。所有 retries 复用同一 permit、reservation、client lease 和 durable mark。

`require_approval` 不新造状态机：复用既有 `AgentApprovalRequest`、`policy_approval` checkpoint、`ApprovalRecord`/lease、`ApprovalGrant`、`ApprovalService` 与 `RunOrchestrator.resume_run()`。等待记录冻结 `action=model.invoke`、resource、canonical `ModelRequest` arguments hash、tenant/identity/agent/run/request/trace 与 checkpoint token；未批准不建立 model reservation。ApprovalService 只能从 durable record/lease 构造 grant，runtime continuation 先校验 approval/lease/tenant/identity/agent/run/action/resource/hash、状态和单次 lease，再调用 `BoundModelInvocationService.complete_approved()`。后者不公开或信任 `soft_approved: bool`，只接受已验证 grant，稳定 operation identity 绑定 approval id，并重新执行 hard route/model catalog/current owner balance；mismatch、stale、duplicate/replay fail closed。批准 continuation 最多触发一次 provider side effect，crash/replay 只恢复同一 settlement。证据复用既有 policy audit、`approval.required|resolved` 与 `run.resumed`，不新增 model authorization event。

该顺序故意选择安全侧：permit 后、mark 前崩溃仍是 reserved/not-started，可安全恢复；mark 后、send 前崩溃虽然可能形成保守假阳性，但必须按 unknown/needs-review 封闭，不能冒险重放。attempts 之间崩溃同样按整个调用 unknown，不实现第二套可恢复 provider retry 状态机。

Composition 启动时只构造并注册 `ControlledOpenAIClientFactory` 的 provider-neutral lazy blueprint，不预构造 `AsyncOpenAI`、`OpenAIProvider`、`OpenAIChatModel` 或 `Agent`。Blueprint 只保存已验证的 frozen deployment/endpoint/model-catalog policy、typed credential resolver 和 client-lease registry，SDK 类型不越过 adapter。首个合法动态 route 完成 hard eligibility、policy allow 或全绑定审批 continuation、reservation 和 permit 后，factory 才构造或复用按冻结 route identity 隔离的 client lease；API、worker、CLI 的统一 lifecycle owner 幂等关闭所有已构造 lease。后续非法请求即使已有其他 route 的 cached client，也不得获取/构造 lease，且本调用 client-construction delta 必须为零。

真实 adapter 使用：

- 显式 `AsyncOpenAI(api_key=typed_secret, admin_api_key="", organization="", project="", webhook_secret="", base_url=plan.canonical_base_url, default_headers={}, max_retries=0, timeout=..., http_client=...)`，使锁定 SDK 的 key/admin/org/project/webhook/base URL 分支不采用 ambient 值；`OPENAI_CUSTOM_HEADERS` 在该版本仍会被 SDK 内部检查，因此不能只靠构造参数或 `trust_env=False` 宣称隔离；
- `httpx.AsyncClient` 使用 `trust_env=False`、`follow_redirects=False` 与私有 `ControlledOpenAITransport`。该 transport 在真正 socket send 前再次 exact 校验 scheme/origin/base path，并从冻结 plan/typed secret/attempt identity 重建封闭出站 header：Authorization 只能来自 typed secret，Content-Type/Accept 使用 adapter 常量，幂等 header 只来自稳定 attempt identity；删除 SDK 产生或 ambient `OPENAI_CUSTOM_HEADERS` 注入的 Authorization、OpenAI-Organization、OpenAI-Project、cookie、proxy auth 及任何非 allowlist header。它不得修改进程全局环境，也不得信任 SDK 合并后的 identity header；
- `OpenAIChatModel` + `OpenAIProvider(openai_client=...)` + `Agent(..., retries=0)`；只运行单 user prompt、无 instructions/message history/tools 的 `await Agent.run(prompt, model_settings=ModelSettings(max_tokens=plan.output_token_cap))`；provider double 必须观察到与冻结 plan 逐字相同的 cap，adapter 不得从 request 或 settings 重算/放大；
- process-local deployment Bulkhead 由核心 permit seam 在 durable mark 和网络前限流，并以 queue timeout 控制等待；
- 唯一有界 retry controller 逐状态接受配置列明的 429/5xx，但只有冻结 endpoint policy 绑定上述 classifier 且私有 transport 从 exact trusted header 得到 `completion_observed=false` 时才重试；这类 attempt 已经 `started`。未绑定 classifier（包括默认官方 endpoint）、信号缺失/畸形/不可信时不重试。可证明 connect-before-send 的异常可按 `not_started` 分类，read timeout、含糊 connect、取消、response id/usage 或部分业务结果一律禁止重试并覆盖任何 false header；
- `Retry-After`/backoff 受单次等待上限、attempt 上限与剩余 total deadline 三重约束；无法容纳下一 attempt 时以 `model.provider_retry_exhausted` 停止；
- 外层可取消 total deadline；进入网络层后发生 read/total timeout 或取消，一律保守标记 side-effect unknown，不由上层自动 retry/fallback。

采用 Adapter + Policy/Decorator + Bulkhead 模式：vendor 构造和 SDK error mapping 留在 adapter；route/预算规则与 permit 顺序留在核心；retry、deadline、bulkhead 是可替换的执行策略。没有引入通用 provider framework 或第二状态机。

### 5. Attempt evidence 与全部 attempt charge 进入既有 settlement

新增 provider-neutral `ModelAttemptEvidence` 与安全 `ModelProviderError`。成功 response 携带 attempts；失败 exception 携带相同安全 attempts、稳定 error code、side-effect state 与 nullable usage。Invocation 在现有一次调用级 settlement 中把 API Contract 5.29 冻结的 `route`、`attempts[]`、`budget_charge` 合并进 `ModelUsageEvidence.decision`，仍使用唯一 started/final event 和稳定 usage event id。

调用只建立一个 reservation，token/cost 上界等于经 checked arithmetic 验证的 `per_attempt_bound * max_attempts`。逐维度矩阵固定为：`not_started` 为零；`started` 且有可信 usage/cost 纳入 actual 聚合；`started` 且任一启用维度 actual 不可得时，不论 completed、确定性 failed 或 retryable status，都保留原调用 reservation、进入 `needs_review` 并阻止 terminal；unknown 同样未决。Cost disabled 时跳过 cost 维度。不可能/矛盾组合或 actual-over fail closed，impact 使用 `max(original_reservation,trusted_actual)`。最终成功前的失败 attempts 不能丢弃：只有全部 started attempts 的启用维度 actual 可得且无异常时，才以聚合 actual 原子替换 reservation、退款并允许 completed/failed terminal。顶层 token/cost 只有在对应维度全部可信时写聚合值，否则为 null/`unavailable`；部分 actual 留在 attempts evidence，绝不把上界或最后成功 attempt 当作整次调用 actual。

Bulkhead/route 拒绝为 `not_started` 且 provider side-effect count 为零。durable mark 后的无法确认状态使用 `model.provider_side_effect_unknown`，token/cost 保持 null/`unavailable`，shared budget 不按零释放并阻止 terminal，沿用现有 unknown/needs-review fencing。可确定失败使用 `model.provider_failed`，attempt/deadline 耗尽使用 `model.provider_retry_exhausted`；raw exception/body/header 不落盘。

不新增 attempt 表或 event type，因为 Phase 18 只需要调用级审计，既有 decision JSON 与 outbox 足够；若未来需要逐 attempt 查询或跨进程恢复 provider 内部 retry，再单独设计 migration，不能在本 change 偷加。

### 6. Composition 负责 client 生命周期，live smoke 与默认门禁分离

`build_agent_execution_services()` 根据完整 settings 一次性验证全部 deployment 并构造 router、fake provider 与真实 provider 的 lazy client factories；它不预构造任何真实 SDK client。任一真实 deployment 的静态 endpoint/credential/capability/price/strategy/ceiling 无效则整个 composition 失败，不留半可用 registry。动态 prompt/output/公式 eligibility 在每次 route plan 阶段完成，通过 reservation 与 permit 后才可构造或获取 client lease。`ModelInvocationService.aclose()` 幂等关闭 router/providers/factory lease registry，template `RuntimeComponents.close()` 在 storage dispose 前调用它；API lifespan、worker 与 CLI 复用同一路径。

默认 CI/local 用网络哨兵和 provider doubles 证明不读 key、不 DNS/HTTP。Opt-in live smoke 使用独立开关和品牌 typed credential，只允许四项前置齐全且另行授权后执行；任一前置缺失唯一写 `hosted-unverified`/CI skipped，条件齐全后的外部阻断才写 `external-blocked`，两者都不影响离线合同 PASS，也绝不把未执行说成真实 E2E 成功。

## Risks / Trade-offs

- [Retry transport 隐藏 attempt 或发生双重重试] → SDK `max_retries=0`、Agent `retries=0`，唯一 retry controller 产生逐 attempt evidence，并以 call-count contract 锁死。
- [测试 double 虚构生产不存在的 completion signal] → 默认/官方 endpoint 的 response retry 集合必须为空；只有 endpoint policy/version 绑定 exact trusted header classifier 时才允许 429/5xx retry，缺失、畸形、不可信或结果已观察一律 unknown/no-retry。
- [取消无法证明服务端未计费] → 网络开始后 timeout/cancel 一律 unknown，禁止自动 retry/fallback并保守占用预算。
- [Base URL allowlist 仍受 DNS 运维影响] → 凭据只发往 exact origin、关闭 proxy/redirect，正式部署由 egress/DNS policy 补强；Harness 不在 startup 做漂移 DNS 猜测。
- [Process-local Bulkhead 不等于集群总并发] → 文档与 evidence 明确作用域；本 change 不伪装为分布式限流，多 worker 总量由每实例配置和部署副本数控制。
- [Agent policy 扩字段影响历史 snapshot] → 新 snapshot 使用 exact v2 schema/id；旧 v1 只接受完整 fake shape 并从已持久化字段投影，partial/corrupt/mixed version fail closed；SQLite/PostgreSQL 共同验证且无数据库 DDL。
- [最大 attempts 放大共享预算或失败 attempt 漏计] → route 以 checked arithmetic 冻结调用级最大 reservation；只有全部启用维度 actual 可信时才统一聚合/退款，任一 started attempt 缺 actual 就保留原 reservation 并进入 needs-review。
- [策略拒绝与 client/mark 顺序产生副作用漂移] → 固定 hard eligibility → soft policy/fallback/approval + 既有 policy audit → reservation → permit → lazy client lease → mark → send；hard/soft/未批准拒绝的全部后续计数均为零，approval grant 全绑定且不得放大 hard limit，client 构造不得联网，mark 后所有 crash window 宁可 unknown 假阳性，也不自动重放。
- [Async protocol 改动触及大量 fake tests] → 先改公共 contract tests和最小 fake adapter，再逐层迁移 invocation；不保留线程池兼容旁路。
- [Secret 进入异常 locals] → 复用现有清空/离开 except 后抛错模式，provider error 只携带安全 DTO，增加唯一 secret fixture 全观测面扫描。

## Migration Plan

1. 先冻结 API/module/config/evidence 文档与本 design 的 acceptance producer/test 映射；建立精确红灯节点后，才把对应 `pending` 行加入当前证据矩阵；不改数据库。
2. 加入新 typed schema 与 fake-compatible profiles，迁移所有 Agent fixtures 到显式 deployment/allowed models；验证默认离线。
3. 引入 immutable route plan 与 async provider protocol，先让 fake 全绿，再实现真实 adapter、lazy client factory/transport 策略和 composition。
4. 用 doubles 完成 config/security/retry/unknown/settlement/lifecycle 验证，随后运行 quality、相关全量 tests、smoke-local 与触及 composition 后的 smoke-service。
5. 真实 live smoke 保持独立 opt-in；本轮没有单独授权，因此唯一预期状态为 hosted-unverified。只有后续授权且本地四项前置齐全后发生外部阻断，才记录 external-blocked。
